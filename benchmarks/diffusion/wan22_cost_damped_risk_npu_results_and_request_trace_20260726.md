# Wan2.2 Cost-Damped Risk NPU 结果与请求执行追踪

## 结论

后续 NPU 测试与策略搜索只使用 8×USP1。最新一轮测试的方案为：

```text
8×USP1 + Wan2.2 专用估时 + Central Pull + Cost-Damped Risk
score = central_wait_s + 0.5 * estimated_service_s
```

100 个正式请求全部成功，另有 1 个 warmup；benchmark 输入、0.03 rps、随机
种子、Tail credit 和阶段边界抢占均保持原样。实测 P95 为 **2431.107s**：

- 相对原文 `2×USP4 / 100 requests` 的 3010.31s：**1.238×**，P95 降
  **19.241%**；
- 相对最初 M8 `1×USP8 / 100 requests` 的 4264.97s：累计 **1.754×**，
  P95 降 **42.998%**；
- 以同一个最初 M8 base 计算，原文方案的 P95 降幅为 29.418%，当前方案为
  42.998%，即累计降幅再增加 **13.580 个百分点**。

当前没有“原策略 8×USP1 / 100 requests”的同拓扑实测，因此 42.998% 是从
M8 到当前方案的拓扑与调度累计收益，不能全部归因于 Cost-Damped Risk。

文末保留之前的 50 请求和 4×USP2 数据，仅用于追溯已完成实验。

每个新实验同时记录两组数：

```text
相对直接对照加速比 = direct_comparator_P95 / experiment_P95
相对最初 base 加速比 = initial_M8_P95 / experiment_P95
相对最初 base P95 降幅 = (initial_M8_P95 - experiment_P95) / initial_M8_P95
```
