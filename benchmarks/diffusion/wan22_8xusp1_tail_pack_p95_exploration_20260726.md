# Wan2.2 8×USP1 Tail Pack 调度探索

## 结论

8×USP1、50 请求 NPU 实验已完成，实测方案为：

```text
Central Pull + Cost-Damped Risk beta=0.95 + Tail Pack
```

50/50 个正式请求成功，实测 P95 为 **1788.961s**。相对上一轮同拓扑
`beta=0.5 + Tail Spread` 的 1885.154s，P95 直接降低 **5.103%**，
加速 **1.054×**；相对最初 M8 `1×USP8` 的 2750.930s，累计降低
**34.969%**，加速 **1.538×**。

Tail 的预算和选择规则保持不变，仍是每 20 个到达请求释放 1 个 credit，并由
满足条件的大请求消耗。新方案只修改两点：

1. Normal 从中央队列拉取时，将 Cost-Damped Risk 的 `beta` 从 0.5 调为 0.95；
2. Tail 不再分散到最空闲 backend，而是复用已有 Tail 的 backend。

调度器只使用已经到达的请求、当前等待时间、Wan2.2 估时和当前 backend 负载。
benchmark 输入、请求总数可见性和负载生成方式均未修改。

固定 benchmark seed 的 50 请求仿真中，P95 从 1841.572s 降到
1781.603s，降低 **3.256%**。200 个随机种子中，该组合在等速 backend
模型下平均降低 **2.288%**，在按真实 trace 加入 backend 速度差异后平均降低
**1.923%**。

这是纯 P95 策略：Tail 的 P99、Mean 和总 Duration 可能变差，不把这些指标作为
本轮否决条件。NPU 实测也验证了这一取舍：P95 改善 5.103%，但 P99 增加
11.787%，Duration 增加 11.107%。

## 为什么继续优化 Tail 放置

当前 NPU trace 的每个请求均已拆成：

```text
到达时间
+ 中央 Normal 等待
+ backend scheduler 等待
+ scheduler 实际计算区间
= E2E
```

其中实际计算区间按每段 `scheduler_select → scheduler_preempt/complete`
累计，不把 Tail 被抢占后的暂停时间误算为计算。

当前 8×USP1、50 请求 NPU 基线为 48 Normal + 2 Tail。两个 Tail 被分散到
backend-0 和 backend-7，分别产生 3 次和 5 次抢占：

| Backend | Normal/Tail | 实际计算(s) | 利用率 | 中央等待均值(s) | Backend 等待均值(s) | E2E 均值(s) | 抢占 |
|---|---:|---:|---:|---:|---:|---:|---:|
| backend-0 | 5/1 | 2980.551 | 99.601% | 670.798 | 162.973 | 1516.005 | 3 |
| backend-1 | 7/0 | 2469.721 | 82.531% | 686.519 | 0.005 | 1044.659 | 0 |
| backend-2 | 6/0 | 2510.283 | 83.887% | 681.085 | 0.006 | 1104.769 | 0 |
| backend-3 | 7/0 | 2437.624 | 81.458% | 684.346 | 0.006 | 1037.314 | 0 |
| backend-4 | 7/0 | 2496.692 | 83.432% | 952.234 | 0.006 | 1313.799 | 0 |
| backend-5 | 4/0 | 2515.203 | 84.051% | 598.445 | 0.006 | 1233.796 | 0 |

backend 建专门的静态快慢路由，而先集中 Tail 干扰。

## NPU 实测结果

### 统一加速比

每一行的“相对最初 base”都使用原始文档中的 M8 `1×USP8 / 50 requests`
P95 `2750.930s` 计算；“直接对照”用于区分本次调度增量和拓扑累计收益。

| 方案 | P95(s) | 相对直接对照 | 相对最初 M8 base |
|---|---:|---:|---:|
| 最初 M8 `1×USP8` | 2750.930 | — | 1.000× / 降 0.000% |
| 原文 `2×USP4` | 2191.560 | 相对 M8：1.255× / 降 20.334% | 1.255× / 降 20.334% |
| 原始 8×USP1 | 1962.350 | 相对 M8：1.402× / 降 28.666% | 1.402× / 降 28.666% |
| 8×USP1 + `beta=0.5` + Tail Spread | 1885.154 | 相对原始 8×USP1：1.041× / 降 3.934% | 1.459× / 降 31.472% |
| 8×USP1 + `beta=0.95` + Tail Pack | **1788.961** | 相对上一行：**1.054× / 降 5.103%** | **1.538× / 降 34.969%** |

新方案相对原始 8×USP1 累计降低 **8.836%**、加速 **1.097×**；相对原文
`2×USP4` 降低 **18.370%**、加速 **1.225×**。相对最初 M8 的
34.969% 是拓扑和多轮调度修改的累计收益，不能全部归因于 Tail Pack。

### 汇总和纯 P95 取舍

本轮只运行 8×USP1、50 请求，使用：

```bash
CENTRAL_PULL_RISK_BETA=0.95
TAIL_ROUTING_MODE=pack
```

benchmark 的请求集、0.05 rps、随机种子、并发、Tail credit 和阶段边界抢占
均保持不变。

| 成功 | Duration(s) | Throughput(req/s) | Mean(s) | Median(s) | P95(s) | P99(s) |
|---:|---:|---:|---:|---:|---:|---:|
| 50/50 | 3324.839 | 0.015038 | 1298.529 | 1452.089 | **1788.961** | 2639.887 |

与上一轮同拓扑 `beta=0.5 + Tail Spread` 实测直接比较：

| 指标 | 上一轮 | Tail Pack | 变化 |
|---|---:|---:|---:|
| P95(s) | 1885.154 | 1788.961 | **降低 5.103%** |
| Mean(s) | 1238.712 | 1298.529 | 增加 4.829% |
| Median(s) | 1303.251 | 1452.089 | 增加 11.421% |
| P99(s) | 2361.531 | 2639.887 | 增加 11.787% |
| Duration(s) | 2992.476 | 3324.839 | 增加 11.107% |
| Throughput(req/s) | 0.016709 | 0.015038 | 降低 9.999% |

因此本轮是有效的“纯 P95”优化，不是无条件更优的通用调度策略。它把两个 Tail
集中到一个 backend，保护其余七个 backend 的 Normal 边界请求；代价是最慢
Tail、P99 和总完成时间变差。
