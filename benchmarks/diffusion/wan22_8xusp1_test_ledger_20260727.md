当前结论：

- req50 从原策略 8×USP1 的 1962.350s 降到 1714.909s，累计降低
  12.609%。Beam 仍是表中最低值，但相对 Queue-Band 只降低
  1.190s / 0.069%，属于噪声量级。
- 因此当前工程参考方案仍采用更简单的 Queue-Band；Beam 只作为算法对照。
- “积压配平 + 波次顺序锁定”相对 Queue-Band 增加 0.799s / 0.047%，相对
  Beam 增加 1.989s / 0.116%，也应视为持平而不是新最优；不继续安排
  req100 NPU。
- req100 没有原策略 8×USP1 和 β=0.95 + Tail Pack 的 NPU 中间点，不能把
  2177.259s 的全部收益归因于最后一个调度改动。
- Beam 实验启动时曾复用残留 backend；模型、拓扑、backend scheduler 和完整
  请求 trace 均一致，结果可比较。后续 runner 必须在启动前检查 8080、
  8091–8098 端口和残留进程。

## 本轮“积压配平 + 波次顺序锁定”NPU 结果

| 指标 | 结果 |
|---|---:|
| 成功请求 | 50/50 |
| Duration | 3676.153s |
| Mean | 1237.783s |
| Median | 1344.217s |
| P95 | **1716.898s** |
| P99 | 2916.647s |
| 抢占 | 0 次 |

策略确实生效：共生成 3 个波次计划，执行 24 个锁定派发，其中 16 次改变了
Queue-Band 当时的选择；planner 总耗时 440.386ms，不是性能瓶颈。

逐请求 trace 说明了为什么 CPU 仿真的收益没有转化成 NPU P95：

- 相对 Queue-Band，Mean 降低 11.250s / 0.901%，但 P95 增加
  0.799s / 0.047%。算法改善了部分较早请求，却没有降低 P95 边界。
- `request-00013` 和 `request-00009` 分别提前 635.789s 和 616.825s；
  但第二个波次锁定后，Queue-Band 会继续优先选择的 `request-00010` 被推迟，
  dispatch 次序从第 17 位变成第 29 位，E2E 增加 749.788s。
- Queue-Band 的 P95 由 `request-00049=1707.868s` 和
  `request-00046=1722.834s` 插值得到；新方案的边界换成
  `request-00049=1710.689s` 和 `request-00047=1721.978s`。两端相抵后，
  P95 反而略高。
- 两个 Tail 仍固定在 backend-7，分别为 2837.187s 和 2992.991s；这轮没有
  改 Tail 策略，也没有发生抢占。

用本轮实际 service residual 做同轮反事实回放时，Queue-Band 为
1718.838s，新方案为 1716.899s，隔离出的调度收益只有 1.940s / 0.113%。
这个信号小于跨轮波动，所以不能算可复现收益。最后一个波次还把 P95 预测为
1670.510s，比实际低 46.388s：计划的 backend 映射只有 4/8 命中，并且
Long 的 612.299s 固定估时比本轮实际平均占用低 18.008s / 2.941%，使关键
释放窗口逐层推迟。

实验名为 `wan22_backlog_leveling_wave_commit_req50_20260727_214750`，
服务器 source HEAD 为 `201d62eafcfaeaa66a4201e1ae5a2f73260de97c`。artifact
独立校验通过，SHA256 为
`7329075602715a71c158331c49ab67477e456867216891953a068e12573b957b`。
状态中的 `COMPLETE_WITH_RESIDUAL_PROCESSES` 来自 168 个

“积压配平 + 波次顺序锁定”相对 fixed Beam 的多种子结果基本持平：

- req50：回退 0.089%，置信区间跨 0；
- req100：改善 0.027%，置信区间跨 0。

测试前，它在两条真实残差路径上分别得到 1695.418s 和 1696.503s，并比对应
fixed Beam 再降低 0.255% / 1.073%。NPU 实测没有复现这部分收益，说明锁定
下一波 8 个请求虽然避免了逐 pull 的计划抖动，也会因 release 误差推迟新的
高风险请求。

这里的 2.598% / 2.502% 是逐 seed 先计算降幅再取均值；若直接用两列 P95
均值相除，会得到 2.627% / 2.511%，两者是不同统计量。其他报告中 Beam
约 2.65% / 1.95% 的数字来自不同 seed cohort，不能与本表直接混算。

ETA 鲁棒波次共识要求同一个 prefix 在 nominal、晚释放和两种 backend 顺序
扰动场景中都不劣于当前 Wave。它的纯 P95 信号方向一致，但绝对收益只有
8.374s / 14.269s，规划耗时约 174ms / 292ms；req50 的 P99 和 makespan
还恶化约 16.8s。基础 Wave 没有在 NPU 上建立可复现收益，因此这个
refinement 暂不测试。

## 已否决的主要方向

| 方向 | 否决原因 |
|---|---|
| Min-Cost Matching / Shadow Price | 前者不改变 Queue-Band 动作；后者 req50/100 分别回退 16.413% / 9.781% |
| Stable Pairwise / Critical-Chain / Branch-and-Bound | 没有稳定超过 Beam，部分 req100 回退，规划开销更高 |
| Dynamic Tail Reselection / Provisional Tail | 多种子无显著收益，真实残差回放回退约 2.5%–3.0% |
| Censored ETA / Near-Release Matching | 相对 Beam 收益接近 0 或回退，真实路径方向不一致 |
| Deadline/Laxity | req50 最好只降 0.235%；真实路径为持平 / 回退 1.412% |
| Backend×输入类型亲和性学习 | 类型交互只有约 0.2%–0.46%，多种子收益约 0，真实回放更差 |
| Robust Gate / Residual Calibration | 只能在部分路径改善，不能稳定超过 Beam |
| Release Coalescing | 有界等待不触发；强制等待约 29s 后 P95 不变 |
